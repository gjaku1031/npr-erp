# 요구사항 명세 — NPR 초등부 업무일지/일일보고 관리 시스템

실제 학원 초등부에서 운영한 팀장·강사용 업무일지. **업무 배정/처리**와 **일일보고 작성·확인**을 관리하고, 일일보고 의무가 없는 다른 팀 인원에게 별도 편의 기능을 제공하며, 학원의 외부 ERP와 연동해 알림장 게시·출결/성적/상담 조회·상담 전송을 수행한다. 공개 저장소에는 외부 ERP의 실제 연동 구현이 없고, 같은 포트(`TttGateway`)를 구현한 모의 구현만 있다(§3.11).

이 문서의 모든 항목은 코드에서 실제 동작을 확인해 도출했다. 코드에서 확인되지 않은 것은 "미확인"으로 표기했다.

## 1. 용어

| 용어 | 의미 |
| --- | --- |
| 팀장 / 강사 / 다른 팀 | 앱의 세 역할(`role='lead'` / `'teacher'` / `'other'`) |
| 마스터 팀장(admin) | `lead_account` 테이블의 계정. 팀장 권한만 있고 강사가 아니다 |
| 임명 팀장 | `teachers.is_lead=1`인 강사. 팀장 화면 + 본인 일일보고 둘 다 사용 |
| 다른 팀 | `teachers.is_other_team=1`인 인원. 강사 현황에서 관리하지만 일일보고·공용 업무 대상이 아닌 편의 기능 전용 역할 |
| M반 / T반 | 월수금반 / 화목토반. 날짜 요일로 자동 판정(일요일은 해당 없음) |
| 특강기간 | 팀장이 켜고 끄는 전역 설정. 날짜별 일일보고는 생성 당시 값을 고정해 보존 |
| 특강 M/T반 | 외부 ERP의 `특강 > 초등` 중 월수금/화목토 요일표를 강사에게 읽기 전용으로 배정한 반 |
| MT 업무 | M(월수금)·T(화목토) 완료를 따로 체크하는 업무 |
| 전체 상담 업무 | 반별 학생 로스터에 상담을 작성해 외부 ERP으로 전송해야 완료되는 업무 |
| 특강상담 업무 | 업무 생성 시 수강년월·특강 학생 로스터를 고정하고 같은 상담 전송 흐름을 쓰는 업무 |
| 외부 ERP | 학원이 쓰는 학원 관리 ERP. 알림장·출결·상담·성적·반 명단의 원천. 코드에서는 `ttt`로 부른다 |

## 2. 역할·권한 모델

근거: `src/api/store.service.ts` (`login`, `getState`, `setTeacherLead`, `setTeacherOtherTeam`), `components/AppRoot.tsx`, `lib/state.tsx`

### 2.1 계정 종류

| 계정 | 저장소 | 로그인 결과 | 강사 화면 |
| --- | --- | --- | --- |
| 마스터 팀장(admin) | `lead_account` | `role='lead'`, `canLead=true`, `isTeacher=false` | 사용 불가(본인 일일보고 없음) |
| 일반 강사 | `teachers` (`is_lead=0`) | `role='teacher'`, `canLead=false`, `isTeacher=true` | 강사 화면만 |
| 임명 팀장 | `teachers` (`is_lead=1`) | `role='lead'`, `canLead=true`, `isTeacher=true` | 팀장 화면으로 시작, 강사 모드 전환 가능 |
| 다른 팀 | `teachers` (`is_other_team=1`) | `role='other'`, `canOtherTeam=true`, `isTeacher=false` | 편의 기능 전용 화면. 일일보고 대상 아님 |

- FR-AUTH-1: 로그인은 아이디로 `lead_account` → `teachers` 순으로 조회하고 scrypt 해시와 비밀번호를 비교한다. 실패 시 "등록된 계정을 찾을 수 없습니다." / "비밀번호가 올바르지 않습니다." 같은 IP·아이디로 10분 안에 5번 틀리면 10분 동안 429로 막는다(인스턴스별 메모리 기준).
- FR-AUTH-2: 로그인에 성공하면 서버가 서명된 세션 쿠키(`npr_session`, HttpOnly, SameSite=Lax, 운영에서 Secure, 12시간)를 내려 준다. 쿠키에는 계정 종류와 아이디만 있고, 역할은 요청마다 DB 권한으로 다시 판단한다. 화면 정보(`role/tid/name/canLead/isTeacher/canOtherTeam`)는 브라우저 `localStorage.npr_session`에 두고 새로고침 시 화면 복구에만 쓴다. 쿠키가 없거나 만료되면 API가 401을 돌려주고 앱은 로그인 화면으로 돌아간다. [로그아웃]은 `POST /api/logout`으로 쿠키를 지운다.
- FR-AUTH-3: "아이디 기억하기" 선택 시 아이디만 `localStorage.npr_saved_id`에 저장한다(비밀번호는 저장하지 않음).
- FR-AUTH-4: 팀장 임명/해제는 팀장이 강사 현황 화면의 토글로 수행한다(`POST /api/teachers/:tid/lead`). 임명은 다중 가능하며 개수 제한이 없다.
- FR-AUTH-5: 다른 팀 권한 부여/해제는 강사 현황의 독립 토글로 수행한다(`POST /api/teachers/:tid/other-team`). 권한을 꺼도 기존 본인 반·상담 이력은 보존하고, 다시 켜면 이어서 사용할 수 있다.

### 2.2 모드 전환

- FR-ROLE-1: 한 계정에 사용 가능한 역할이 둘 이상이면 헤더에 해당 역할만 포함한 전환 세그먼트가 보인다.
- FR-ROLE-2: 전환 시 열린 모달을 닫고 일일보고를 목록 모드로 되돌린 뒤, 해당 역할의 첫 화면(팀장=대시보드 / 강사=대시보드 / 다른 팀=본인 반 동기화)으로 이동하며 상태를 재조회한다(재조회 전까지 스플래시).
- FR-ROLE-3: 로그인 응답의 `canLead`/`isTeacher`/`canOtherTeam`에 없는 역할로는 전환할 수 없다(마스터 팀장은 강사 모드 불가).

### 2.3 화면(내비게이션)

| 팀장 | 강사 | 다른 팀 |
| --- | --- | --- |
| 대시보드 · 업무 · 일일보고 · 강사 현황 · 공지사항 · [+ 업무 생성] | 대시보드 · 내 업무 · 일일보고 | 본인 반 동기화 · 상담일정 · 알림장 |

- FR-NAV-1: 헤더에는 모든 역할 공통으로 다크 모드 토글·본인 이름 아바타·[로그아웃]이 있다. 다크 모드 선택은 `localStorage.npr_dark`에 저장돼 브라우저에 유지된다.

## 3. 기능 요구사항

### 3.1 업무 (Task)

근거: `src/api/store.service.ts`(`createTask`/`updateTask`/`buildTask`/`setTaskStatus`/`setTaskMt`), `components/modals/ModalHost.tsx`, `components/screens/LeadTasks.tsx`, `components/screens/TeacherTasks.tsx`

- FR-TASK-1 (생성/수정, 팀장): 업무 이름(필수), 내용(마크다운), 태그(필수), 배정 범위, 시작일·마감 기한(필수), 참고 링크 목록, 완료 조건 토글을 입력한다.
- FR-TASK-2 (배정): "전체 강사에게 배정"이 켜지면 `scope="all"`(현재 등록된 전 강사가 담당), 끄면 강사를 개별 선택(`scope=["이름",…]`)한다. 개별 선택 시 최소 1명이 필요하다.
- FR-TASK-3 (완료 조건): `reportReq`(텍스트 보고 필수), `attachReq`(첨부파일 필수), `mt`(MT 업무), `counsel`(전체 상담 업무), `specialCounsel`(특강상담 업무)을 켤 수 있다. 일반상담과 특강상담은 상호 배타이며 클라이언트와 서버가 모두 동시 선택을 거부한다.
- FR-TASK-4 (D-day): 마감 기한과 앱 기준 '오늘'로 D-day를 계산해 `D-n` / `D-DAY` / `완료`(마감 지남)로 표시하고, D-2 이내는 강조(빨강)한다.
- FR-TASK-5 (정렬): 업무는 `sort` 오름차순으로 조회되며, 신규 업무는 `MAX(sort)+1`로 맨 뒤에 붙는다. (드래그 등 정렬 변경 UI 없음)
- FR-TASK-6 (삭제, 팀장): 업무 삭제 시 해당 업무의 모든 강사 처리 상태(`task_status`)도 함께 삭제된다. 확인 대화상자를 거친다.
- FR-TASK-7 (강사 처리): 일반 업무는 [V 완료] / [X 미완료]로 표시한다. 완료 조건 미충족 시 완료 버튼이 비활성화된다.
- FR-TASK-8 (보고 작성): 강사는 업무별 텍스트 보고와 첨부파일(파일당 4MB 이하, base64 data URL로 저장)을 남긴다. 텍스트는 500ms 디바운스로 자동 저장된다.
- FR-TASK-9 (진행 표시, 팀장): 업무 목록·상세에 `완료 인원/총 인원`과 진행 막대를 표시하고, 상세에서 강사별 상태·보고 텍스트·첨부를 볼 수 있다.
- FR-TASK-10 (필터): 팀장은 전체/진행 중/완료 + 태그로, 강사는 전체/진행 중/완료로 목록을 거른다.

#### 3.1.1 MT 업무

- FR-MT-1: `mt=1` 업무는 강사가 [M(월수금)] / [T(화목토)] 두 버튼을 독립적으로 토글한다.
- FR-MT-2: 상태는 `m_done && t_done → 'done'`, 하나만 → `'undone'`, 둘 다 아니면 → `'none'`으로 서버가 파생한다.
- FR-MT-3: MT 업무에는 텍스트/첨부 완료 조건 검증이 적용되지 않는다(`setTaskMt`는 검증 없음).

#### 3.1.2 전체 상담 업무

근거: `src/api/store.service.ts`(`upsertCounselRoster`/`saveCounselDraft`/`markCounselSynced`), `pages/api/[[...slug]].ts`(`/api/counsel/*`), `components/screens/TeacherTasks.tsx`(`CounselPanel`), `components/modals/ModalHost.tsx`(`CounselSendModal`)

- FR-CNS-1 (로스터 동기화): 강사가 담당 반을 선택하고 [학생 로스터 동기화]를 누르면 외부 ERP에서 해당 반 학생(학번·이름·어머니 전화)을 가져와 `counsel_entries`에 반영한다.
- FR-CNS-2 (보존 갱신): 재동기화 시 이름·전화만 갱신하고 기존 상담 주제/내용/전송 상태는 보존한다. 현재 로스터에 없는 학생(퇴원 등)은 삭제하되, **로스터가 비어 있거나 전송 결과가 `pending`이면 기존 항목을 보존**해 드래프트 손실·중복 전송을 막는다.
- FR-CNS-3 (상담 작성·전송): 학생별 [상담 작성·전송] → 주제·내용 입력 → [동기화(외부 ERP 전송)]. 전송 직전 주제·내용을 먼저 저장하므로 전송이 실패해도 내용이 남는다.
- FR-CNS-4 (비공개 기본): 외부 ERP 상담은 공개수준 0(비공개)으로 전송된다.
- FR-CNS-5 (검증된 전송만 완료): 상담 날짜·주제·본문 지문을 공유 Turso primary의 임의 소유 토큰 guarded UPDATE로 `pending/claimed` 원자 선점하고, ERP 사전 건수와 `posting`을 원격 저장한 뒤 외부 ERP에 한 번만 쓴다. 원생코드·일자·주제·본문 9자 이상 미리보기의 저장 전후 건수가 증가한 경우에만 `synced=1`이 된다. fresh `claimed`는 3분 lease 동안 다른 요청이 건드리지 않고, lease가 끝난 동일 선점만 CAS로 재시도 가능 상태에 되돌린다. 이전 소유자는 회수 뒤 단계 전환이 거부된다. `posting` 뒤 결과나 최종 DB 영속을 확인하지 못하면 202와 [전송 결과 확인]을 표시해 재전송을 막는다. `posting` 결과 확인은 ERP 읽기만 하며 저장 POST를 반복하지 않는다. 정상 전송 항목은 [수정·재전송]으로 바뀐다.
- FR-CNS-8 (안정 대상 키): 화면의 임시 엔트리 ID가 오래됐으면 서버는 로그인 강사에 바인딩된 `(taskId, teacher, cls, scode)`로 정확히 한 행을 재해결한다. 기존 ID와 자연키가 충돌하거나 대상이 없으면 ERP 쓰기 전에 중단한다.
- FR-CNS-6 (진행 노출): 강사별 `전송 synced/total`을 내 업무 목록·상세와 팀장 업무 상세에 표시한다.
- FR-CNS-7 (모 번호 경고): 어머니(HP모) 번호가 비어 있으면 ⚠ 없음으로 표시하고 반 단위로 "모 번호 없음 N명" 배지를 띄운다. 아버지 번호로 대체하지 않는다.

#### 3.1.3 특강상담 업무

- FR-SCNS-1 (생성 스냅샷): 특강상담 생성 시 최근 성공한 `special_sync_month`를 `tasks.special_source_month`에, 당시 담당 강사명을 `tasks.special_assignees`에 저장하고, 담당 강사의 해당 월 로스터를 `counsel_entries`로 복사한다. `scope='all'`도 생성 당시 강사로 고정하며, 먼저 특강 반 동기화가 되어 있지 않으면 생성을 거부한다.
- FR-SCNS-2 (불변 대상): 같은 월을 다시 동기화하거나 다른 월로 넘어가도 이미 만든 업무의 반·학생·진행률은 바뀌지 않는다. 고정된 상담 업무의 종류나 배정 범위도 변경할 수 없다.
- FR-SCNS-3 (선택 반 연락처): 중앙 반 동기화 때는 전체 학생 상세를 읽지 않는다. 강사가 특정 특강 반을 동기화할 때 그 업무의 고정 학생만 최대 4개 병렬로 조회해 어머니 연락처를 보강하고, 일부 실패는 기존 값·상담 드래프트를 보존한 채 경고한다.
- FR-SCNS-4 (상담 재사용): 상담 작성·비공개 전송·전송 완료 집계는 일반상담과 같은 강사 개인 외부 ERP 계정 경로를 사용한다. 특강 반을 읽는 학원 단위 조회는 상담을 쓰지 않는다.
- FR-SCNS-5 (대상 없음): 특강 학생이 없는 담당자는 `noTarget=true`로 표시하고 업무 전체 완료 진행률을 막지 않는다.
- FR-SCNS-6 (생성 멱등성): 특강상담 생성 모달은 하나의 `requestId`를 성공 확인 전까지 유지한다. 응답 지연·재시도로 같은 요청이 다시 도착해도 서버는 같은 업무 ID를 반환하고 고정 로스터를 두 번 복사하지 않는다. 같은 `requestId`에 다른 내용은 409로 거부한다.

### 3.2 일일보고 — 정의/관리 (팀장)

근거: `components/screens/LeadJournal.tsx`, `src/api/store.service.ts`(`createJournal` 등)

- FR-JNL-1: 팀장은 날짜를 골라 그 날짜의 일일보고(체크리스트)를 생성한다. 이미 있으면 무시된다.
- FR-JNL-2 (항목 복사): 생성 시 **오늘 날짜의 체크리스트 항목**을 복사한다. 오늘 항목이 없으면 대상 날짜 **이전의 가장 최근 일일보고** 항목을 복사한다.
- FR-JNL-3: 항목별로 [보고 필수 ↔ 보고 선택]을 토글하고, 항목을 추가·삭제할 수 있다. 단 **지난 날짜(`kind='past'`)는 수정 불가**(추가/삭제/필수토글 UI 미노출).
- FR-JNL-4: 날짜 목록에는 예정 / 오늘·진행 중 / 마감 배지와 `체크리스트 N항목 · 제출 X/Y명`을 표시한다.
- FR-JNL-5 (삭제): 날짜별 일일보고 삭제 시 체크리스트 항목과 **그 날짜의 제출물까지 함께 삭제**된다.
- FR-JNL-6 (주간테스트 기간): M반·T반 각각의 주간테스트 시행일을 날짜로 지정한다(`settings.wtest_m` / `wtest_t`). 강사 4단계 성적 조회 날짜로 쓰인다.
- FR-JNL-7 (제출 현황): 선택 날짜의 강사별 버블(미제출 `—` / 확인 대기 `…` / 확인 완료 `✓`)을 표시하고, 제출된 버블을 클릭하면 그 날짜 보고 열람 모달이 열린다. 미래 날짜는 "아직 시작 전" 안내만 표시한다.
- FR-JNL-8 (특강기간): 생성 날짜 옆 전역 특강기간 토글은 `enabled`와 마지막 선택 날짜를 함께 저장한다. 토글을 끄기 전 생성되는 일일보고는 `journals.special_period=1`로 고정되고, 토글을 나중에 꺼도 기존 특강 보고·동기화·상담 이력은 유지된다.
- FR-JNL-9 (특강 기준일): 특강기간이 켜진 동안 생성 화면의 날짜가 바뀌면 그 날짜를 `special_sync_date`로 저장한다. 강사 현황의 동기화 버튼은 토글이 켜진 동안만 표시한다.

### 3.3 일일보고 — 작성 위저드 (강사)

근거: `components/screens/Wizard.tsx`, `lib/state.tsx`(`enterWizard`/`enterStep`/`submitWizard`)

5단계 고정: **1 체크리스트 → 2 알림장 → 3 상담 확인 → 4 출결 확인 → 5 업무 확인**

- FR-WIZ-1 (진입): 강사 일일보고 화면에서 [작성 시작] / (draft가 있으면) [이어서 작성]. 오늘 일일보고가 생성돼 있지 않으면 "팀장이 생성하면 작성할 수 있습니다" 안내가 뜬다.
- FR-WIZ-2 (좌측 레일): 5단계 목록과 `n/5 단계 완료` 진행 막대를 표시한다. 레일 클릭으로 **어느 단계로든 자유 이동**할 수 있다(순차 강제 아님). [다음 ›] 버튼만 현재 단계 완료를 요구한다.
- FR-WIZ-3 (임시저장): [임시저장]으로 위저드 상태 전체를 `daily_reports.payload`(status='draft')에 저장한다.
- FR-WIZ-4 (제출): 5단계에서 **5개 단계가 모두 완료**여야 [일일보고 제출]이 활성화된다. 제출 시 payload 저장 + `status='submitted'`, `confirmed=false`, 제출 완료 화면 표시.

#### 1단계 · 체크리스트
- 팀장이 만든 오늘 항목을 체크하고, 항목별 확인 결과 텍스트와 파일(4MB 이하)을 첨부한다.
- 체크한 항목에만 보고 입력란이 열린다. `보고 필수` 항목은 배지로 구분된다.

#### 2단계 · 알림장
- [외부 ERP 동기화]로 담당 반별 알림장 작성 여부를 조회한다. 이미 작성돼 있으면 제목·본문을 불러와 [수정하기]로 편집, 없으면 새로 작성한다.
- 게시 폼: 제목(필수)·내용(필수) + URL 최대 2개 / 이미지 최대 5개 / 파일 최대 2개.
- 게시는 외부 ERP의 알림장으로 전송된다. 기존 글이 있으면(`cmtId`) 제자리 수정, 없으면 신규 게시.
- 담당 반이 없으면 "강사 현황에서 담당 반을 지정해 주세요" 안내를 띄운다.
- 일반 날짜는 해당 요일의 일반 반만, 특강 날짜는 일반 반 + 같은 요일의 특강 반을 중복 제거해 처리한다.

#### 3단계 · 상담 확인
- 단계 진입 시마다 외부 ERP에서 **오늘 상담 기록**(학생 · 주제 · 내용)을 자동 재조회하며, [↻ 다시 동기화]로 언제든 다시 부를 수 있다. 조회 실패 시 직전 데이터를 유지한다.
- "오늘 상담 내용을 모두 확인했습니다" 토글로 확인 처리한다.

#### 4단계 · 출결 확인 (+ 주간테스트 성적)
- 담당 반 칩으로 반을 전환하며 출결표(학생·상태)를 본다. 상태 배지 색: 결석·휴강=빨강, 지각·조퇴·외출·결과·예정=주황, 그 외=초록. 헤더에 `출석 n · 지각 n · 결석 n` 요약.
- 학생 이름 호버 시 **학교 · 어머니 전화** 툴팁.
- FR-WIZ-4A (날짜 분리): **선행/심화 과제 이행(A/B/C)은 일일보고 날짜(오늘)** 자료로, **주간테스트 성적(총점·석차·평균·지도의견)은 팀장이 지정한 주간테스트 시행일** 자료로 각각 조회해 학생 이름으로 조인한다. 반 이름에 `T`가 포함되면 `wtest_t`, 아니면 `wtest_m`을 쓴다.
- FR-WIZ-4B (등급 표기): 과제 이행 문자열 → `미이행`=**C(빨강)**, `미흡`=B, `없음`/`문제`=A, 빈값=**미입력**(회색, 작게).
- FR-WIZ-4C (성적 표기): 총점 **70점 미만은 빨강**, 그 외 강조색. 옆에 석차, 호버 시 `평균 · 석차/응시자 · 지도의견`.
- 주간테스트 날짜가 설정되지 않았으면 성적 열 대신 "주간테스트 기간이 설정되지 않았습니다. (팀장 · 일일보고 관리에서 M반/T반 날짜 설정)" 안내를 띄운다.
- "오늘 담당 반의 출결 기록을 모두 확인했습니다" 토글로 확인 처리한다.
- 반 목록은 2단계와 같은 날짜별 일반/특강 병합 스냅샷을 사용한다.

#### 5단계 · 업무 확인
- **오늘(일일보고 날짜)이 기간에 포함되는 업무**(시작일 ≤ 오늘 ≤ 마감일)만 나열한다.
- 일반 업무는 [V 완료] / [X 미완료]로 표시(완료 조건 미충족 시 완료 비활성 + "텍스트 보고 필수 — 내 업무에서 작성" 안내).
- MT 업무는 M/T 버튼을, 전체 상담 업무는 "내 업무에서 작성·전송" 안내를 노출한다.
- 업무 제목 클릭 시 업무 상세 모달이 열린다.

### 3.4 일일보고 — 제출/확인 흐름

근거: `src/api/store.service.ts`(`submitReport`/`confirmReport`/`reopenReport`), `components/modals/ModalHost.tsx`(`LogViewModal`), `components/screens/TeacherLog.tsx`

- FR-RPT-1: 강사·날짜당 보고는 1건이다(`UNIQUE(teacher, date)`). 상태는 `draft` → `submitted`.
- FR-RPT-2 (확인, 팀장): 보고 열람 모달에서 [보고 확인 처리]. **제출(`status='submitted'`)된 보고만 확인 가능**하며, 미제출 상태에서 확인을 시도하면 400 "제출된 보고만 확인할 수 있습니다."로 거부된다.
- FR-RPT-3 (재수정): 강사는 제출 후 [수정하기]로 `draft`로 되돌릴 수 있으나, **확인 완료된 보고는 되돌릴 수 없다**(400 "확인 완료된 보고는 수정할 수 없습니다."). 제출 완료 화면의 [제출 내용 수정] 버튼도 확인 완료 시 비활성화된다.
- FR-RPT-4 (재제출): 재제출하면 `confirmed`가 다시 `false`로 초기화된다.
- FR-RPT-5 (열람 내용): 열람 모달은 실제 payload를 그대로 렌더한다 — 1단계 체크/보고 텍스트, 2단계 반별 게시 여부·제목, 3단계 상담 목록(열람 시점에 외부 ERP 재조회), 4단계 확인 여부, 5단계 업무별 V/X/미표시.
- FR-RPT-6 (날짜별 현황): 팀장 대시보드는 오늘 기준 `제출 X/Y`·확인 대기 수를, 일일보고 화면은 **날짜별 실제 제출/확인 현황**을 표시한다.
- FR-RPT-7 (표시 교정): `status != 'submitted'`인데 `confirmed=1`인 행은 화면상 확인 완료로 보이지 않도록 서버가 `submitted && confirmed`로 계산해 내려준다.
- FR-RPT-8 (지난 보고): 강사는 본인의 과거 제출 보고 목록(날짜 · 알림장 게시 건수)을 보고 클릭해 열람할 수 있다.
- FR-RPT-9 (반 스냅샷): 보고 payload는 `specialPeriod`와 실제 처리한 중복 제거 `classSnapshot`을 저장한다. 이후 특강 반을 재동기화해도 과거 보고의 알림장·출결 반 목록은 바뀌지 않는다.

### 3.6 캘린더

근거: `components/Calendar.tsx`, `components/screens/shared.tsx`(`CalendarCard`)

- FR-CAL-3 (스크롤): **월 페이지 전환이 아니라 주 단위 연속 무한 스크롤**이다. 초기에는 이번 주 기준 위 2주·아래가 보이고, 위/아래로 스크롤하면 4주씩 확장된다. 1일이 포함된 주에 `YYYY년 M월` 라벨이 붙는다. [오늘] 버튼으로 초기 위치로 되돌린다.

### 3.7 일정 (Event)

- FR-EVT-1: 일정은 개인일정(`personal`)과 팀 일정(`team_event`) 2종이다. 팀장이 만든 개인일정의 소유자는 `'lead'`, 강사가 만들면 해당 `tid`.
- FR-EVT-2 (가시성): 팀장은 `lead` 소유 + `team` 일정을, 강사는 `team` + 본인 `tid` 일정을 본다.
- FR-EVT-3 (태그): 팀 일정은 업무 태그를 재사용하거나 `일정`, 개인일정은 `개인일정`으로 고정된다.
- FR-EVT-4 (수정/삭제): 팀 일정은 팀장이, 개인일정은 소유자만 수정·삭제 버튼을 볼 수 있다(`mine` 플래그). 수정 시 소유·유형은 유지되고 제목·메모·기간·태그만 바뀐다.

### 3.8 태그

- FR-TAG-1: 태그는 이름·색상·이모지·정렬을 가진다. 색상은 프리셋(올리브/블루/옐로) 또는 컬러픽커 HEX 직접 지정.
- FR-TAG-2 (고정 태그): **`상담`은 전체 상담 업무의 기본 태그로 삭제·이름변경이 불가**하다. 태그 관리 화면에서 `🔒 고정` 배지가 붙고 이름 입력란·삭제 버튼이 사라진다(색상·이모지는 변경 가능). 서버는 시도 시 400으로 거부하고, DB에 없으면 부팅 시 자동 생성한다(블루 · 💬).
- FR-TAG-3 (이름 변경 연쇄): 태그 이름을 바꾸면 그 태그를 쓰는 업무·일정의 태그도 함께 갱신된다. 중복 이름은 400.
- FR-TAG-4 (삭제 폴백): 태그 삭제 시 그 태그를 쓰던 업무와 일정은 `행정` 태그로, `행정`이 없으면 남은 일반 태그 가운데 순서가 가장 앞선 태그로 옮겨진다. 옮길 태그가 없는데 그 태그를 쓰는 업무나 일정이 있으면 삭제를 거부한다(409).
- FR-TAG-5 (기본 태그): 신규 부트스트랩 시 채점 · 상담 · 교재 · 행정 · 행사 5종이 생성된다.

### 3.9 강사 현황 (팀장)

근거: `components/screens/LeadMapping.tsx`, `src/api/store.service.ts`(`createTeacher` 등)

- FR-TCH-1 (등록): 이름 · 아이디 · 초기 비밀번호로 강사를 등록한다. 아이디 중복은 400.
- FR-TCH-2 (담당 반): 강사별 `월수금반`·`화목토반`을 정규 반 동기화 결과의 읽기 전용 칩으로 표시한다. 오늘 요일에 해당하는 그룹에 `오늘 적용` 배지가 붙고, 하단에 "오늘 · <그룹> 적용 — <강사> 담당: <반 목록>"을 요약한다. 이 값이 일일보고 2·4단계와 전체 상담 업무의 반 목록이 된다. 사용자는 반을 직접 추가·삭제할 수 없고 정규 반 동기화만 두 그룹을 갱신한다.
- FR-TCH-2A (특강 담당 반): 일반 그룹 아래 `특강 월수금반`·`특강 화목토반`을 특강 반 동기화 결과의 읽기 전용 칩으로 표시한다. 사용자는 반을 직접 추가·삭제할 수 없고 특강 반 동기화만 두 그룹을 갱신한다. `POST /api/teachers/:tid/classes`는 정규·특강을 포함한 모든 반 그룹 직접 수정 요청을 400으로 거부한다.
- FR-TCH-2B (특강 반 동기화): 특강기간이 켜지면 기준일·최근 수강년월과 [특강 반 동기화] 버튼을 표시한다. 로딩·성공·부분 매칭·실패 및 미매칭 강사/반·미지원 요일표를 구분해 보여준다.
- FR-TCH-2C (정규 반 동기화): [정규 반 동기화]는 중앙 송파 본원의 `초등부 > 초등4/5/6` 활성 반코드·요일표와 등록 강사별 외부 ERP 계정의 반목록을 교차해 일반 월수금·화목토 그룹을 한 번에 갱신한다. `[연장]`은 반명 기준으로 항상 제외한다. 한 계정에만 보이는 신규 반 또는 기존 담당자와 같은 반은 자동 배정하고, 한 계정에만 보여도 기존 담당자가 다르면 재배정하지 않고 충돌로 보고한다. 복수 계정에 보이는 반은 기존 담당자가 후보 중 유일할 때만 유지한다. 계정 조회 실패·미귀속·충돌이 하나라도 있으면 일반 그룹 전체를 변경하지 않으며 특강 그룹은 언제나 보존한다. 중앙 목록의 복수 `Rs2` 강사명은 담당 판정에 사용하지 않는다.
- FR-TCH-3 (외부 ERP 계정): 강사별 외부 ERP 아이디·비밀번호를 입력해 저장한다. 저장 전 **포트의 계정 확인(`verifyAccount`)으로 검증**하고(모의 구현은 아이디·비밀번호가 비어 있지 않으면 통과) 성공 시 회원명을 토스트로 알린다. 실패 시 저장하지 않고 사유를 표시한다. 비밀번호는 AES-256-GCM으로 암호화 저장되고 화면에 다시 노출되지 않으며(연결됨/미연결 배지만), 빈 값으로 저장하면 기존 비밀번호가 유지된다.
- FR-TCH-4 (팀장 임명): "팀장 권한 부여" 토글(§2.1).
- FR-TCH-4A (다른 팀 권한): "다른 팀 권한 부여" 토글로 관리 명단에는 유지하되 일일보고·제출 통계·공용 업무 배정에서 제외한다.
- FR-TCH-5 (비밀번호 변경): 팀장이 강사의 앱 로그인 비밀번호를 직접 지정해 변경한다.
- FR-TCH-6 (삭제): 강사 삭제 시 해당 강사의 처리 상태·일일보고 제출물·리마인드 기록·개인일정과 다른 팀 본인 반 스냅샷·개인 상담일정·학생 상담/부재 이력이 함께 삭제된다. 확인 대화상자를 거친다.
- FR-TCH-7 (제출 배지): 강사 상세에 오늘 미제출 / 오늘 제출 / 오늘 확인 완료 배지를 표시한다.

### 3.9A 다른 팀 편의 기능

- FR-OTH-1 (본인 반 동기화): 로그인한 인원의 외부 ERP 계정만 사용해 기준일의 담임 반과 현재 수강 학생을 월별 스냅샷으로 저장·조회한다. `[연장]` 반은 제외하되 미지원 요일표의 담당 반·학생은 본인 화면에 보존한다.
- FR-OTH-2 (파괴적 변경 보호): 기존 학생이 빠지는 동기화는 별도의 새 ERP 조회 결과가 동일할 때만 적용하며, 불일치·실패 시 기존 명단을 보존한다.
- FR-OTH-3 (상담일정): 사용자는 최신 본인 반 학생을 대상으로 개인 상담일정을 생성·삭제하고 학생별 상담 작성·부재/문자·외부 ERP 전송 상태를 직접 확인한다. 업무와 대상은 소유 `tid`에 바인딩되고 팀장 공용 업무 화면에는 나타나지 않는다.
- FR-OTH-4 (알림장): 최신 본인 반의 반명만 대상으로 날짜별 기존 알림장을 조회·수정·게시한다. 일일보고 생성·작성·제출과 무관하다.
- FR-OTH-5 (제외): 다른 팀 인원은 팀장 대시보드·일일보고 화면의 제출 분모와 공용 업무 `all`/지정 배정 후보, 정규·특강 전체 동기화 대상에서 제외된다.

### 3.10 대시보드

- FR-DASH-1 (팀장): 진행 업무 수 · `오늘 보고 제출 X/Y`(미제출 n명 · 확인 대기 n명) · 마감 임박(D-2 이내 & 미완료) 3개 지표 + 캘린더 + 업무별 진행 막대 + 강사 제출 버블 + 공지 요약(노출 중 상위 2건).
- FR-DASH-2 (강사): 미완료 업무 · 오늘 일일보고 상태(미제출/확인 대기/확인 완료) · 마감 임박(내 업무) 3개 지표 + 캘린더.

### 3.11 외부 ERP 연동

근거: `src/ttt/ttt.gateway.ts`(포트), `src/ttt/ttt.service.ts`(연동 규칙), `src/ttt/counsel-write.ts`(상담 쓰기 확인 규칙), `src/ttt/ttt.mock.ts`(모의 구현)

앱은 외부 ERP를 `TttGateway` 포트로만 읽고 쓴다. 운영에서는 강사별 ERP 계정으로 로그인하는 구현을 썼고, 공개 저장소에는 결정적인 가상 데이터를 돌려주는 `MockTttGateway`만 있다. 아래 규칙은 포트 위의 서비스 계층에 있으므로 모의 구현에서도 그대로 동작한다.

| 기능 | 계정 | 실패 시 |
| --- | --- | --- |
| 알림장 조회/게시 | 강사 계정(없어도 호출) | 오류 |
| 출결·상담·성적·명단 조회 | **강사 본인 계정 필수** | 빈 배열 |
| 주간테스트 PPT용 성적·출결 조회 | **강사 본인 계정 필수** | 원인을 담아 실패(엄격 조회) |
| 본인 반·학생 명단, 학생 연락처·마지막 상담일 | **강사 본인 계정 필수** | 원인을 담아 실패(엄격 조회) |
| 상담 쓰기·재확인·진단 | **강사 본인 계정 필수** | 확인 불가 오류(§4.2 아래) |
| 특강 반·특강 원생 연락처 | 학원 단위 조회(강사 계정 아님) | 기존 스냅샷 유지 + 오류 |

- FR-TTT-1: 출결·상담·성적·명단은 강사 본인 계정이 없으면 조회하지 않는다. 다른 강사의 자료가 공유 계정으로 노출되는 것을 막기 위함.
- FR-TTT-2: 일반 조회 실패는 가짜 데이터 대신 빈 값을 반환한다. 일부 반이 조용히 빠지면 안 되는 작업(PPT 생성, 반 적용, 학생 상세)은 엄격 조회로 실패를 그대로 알린다.
- FR-TTT-3: 상담 쓰기는 비멱등이고 응답이 성공 여부를 알려 주지 않는다. 그래서 저장 전 같은 원생·일자·주제·본문의 상담 수를 세고, 전송 시도를 DB에 먼저 기록(`onBeforePost`)한 뒤 저장 요청을 한 번 보내고, 다시 읽어 수가 늘었을 때만 성공으로 본다. 긴 본문은 목록에 9~10자 미리보기로만 오므로 충분히 긴 정확한 앞부분도 같은 본문으로 센다. 저장 요청 뒤의 모든 실패(응답 유실, 로그인 화면 응답, 다시 읽기 실패, 수가 늘지 않음)는 실패가 아니라 확인 불가(`TttCounselWriteIndeterminateError`)이며 저장 요청을 반복하지 않는다. 확인 불가 건은 읽기 전용 재확인으로만 확정한다.
- FR-TTT-4: 외부 ERP는 한국 실시간 시스템이므로 상담일자는 **KST 실제 오늘**을 쓴다(데모용 `APP_TODAY` 고정값과 분리).
- FR-TTT-5: 특강 요일표는 월수금(`1010100`)과 화목토(`0101010`)만 지원한다. 다른 요일표는 제외·보고하고, 강사명은 trim 후 정확히 일치할 때만 매칭한다.
- FR-TTT-6: 전체 조회 성공 및 정확한 강사 매칭 1명 이상일 때만 트랜잭션으로 특강 스냅샷을 교체한다. 조회·분류·무매칭 실패 시 기존 배정은 변하지 않는다.
- FR-TTT-7 (모의 구현): 반·원생·성적·출결은 강사 이름·반 이름·날짜에서 결정적으로 만든다. 같은 입력이면 재시작해도 같은 값이 나와 "조회 → 확인 → 적용"처럼 두 번 읽는 흐름이 실제와 같이 동작한다. 게시한 알림장과 저장한 상담은 프로세스 메모리에만 남는다. 이름·학교·연락처(`010-0000-XXXX`)는 모두 지어낸 값이다.

## 4. 비즈니스 규칙

### 4.1 완료 판정

| 업무 유형 | 강사 개인 완료 | 팀장 집계(`doneCount`) |
| --- | --- | --- |
| 일반 | `task_status.status === 'done'` | 담당자 중 `status='done'` 인원 |
| MT | `m_done && t_done` (서버가 `status='done'`으로 파생) | 위와 동일 |
| 전체 상담 | `total > 0 && synced >= total` (담당 학생 **전원 외부 ERP 전송**) | 담당자 중 위 조건 충족 인원 |
| 특강상담 | `noTarget || (total > 0 && synced >= total)` | 대상 없음 또는 고정 학생 전원 전송인 담당자 수 |

- BR-DONE-1: 전체 상담 업무는 `total === 0`(로스터 미동기화)이면 **완료가 아니다**.
- BR-DONE-2: 상담 전송 전에 명확히 실패하면 해당 항목은 `synced=0`으로 남아 완료에 집계되지 않는다. POST 뒤 결과 미확인이나 ERP 성공·앱 저장 지연 상태는 중복 방지를 위해 같은 상담을 재전송하지 않고 외부 ERP/앱 상태를 먼저 확인한다.
- BR-DONE-3: 일반 업무를 완료로 표시하려면 `report_req`면 보고 텍스트가 비어 있지 않아야 하고, `attach_req`면 첨부가 1개 이상이어야 한다. 서버가 400으로 거부한다("텍스트 보고가 필요합니다." / "첨부파일이 필요합니다.").
- BR-DONE-4: 완료 조건 검증은 `report_req` → `attach_req` 순으로 걸리며, MT 업무에는 적용되지 않는다.
- BR-DONE-5: 팀장 업무 목록의 `완료` 필터 = `doneCount >= total`.

### 4.2 위저드 단계 완료 게이트

| 단계 | 완료 조건 |
| --- | --- |
| 1 체크리스트 | 항목이 1개 이상 존재 **AND** 모든 항목이 체크됨 **AND** `required` 항목은 보고 텍스트가 비어 있지 않음 |
| 2 알림장 | 오늘 담당 반이 **0개**이거나, `nbSync === 'done'` **AND** 담당 반 전부 `written` |
| 3 상담 확인 | `counselOk === true` (확인 토글) |
| 4 출결 확인 | `attOk === true` (확인 토글) |
| 5 업무 확인 | **오늘 기간 업무** 전부가 `mt`·`counsel`·`specialCounsel` 중 하나이거나 `myStatus[id] != null`(V/X 표시됨) |

- BR-GATE-1: 5단계 게이트에서 **MT 업무와 일반/특강 상담 업무는 제외**된다(제출 조건에 걸지 않음).
- BR-GATE-2: 5단계 대상은 `start <= 오늘 <= due`인 업무뿐이다(기간 밖 업무는 제출을 막지 않는다).
- BR-GATE-3: 제출 버튼은 **5개 단계 전부 완료**일 때만 활성화된다. 단계 이동 자체는 레일 클릭으로 자유롭다.
- BR-GATE-4: 2단계에서 담당 반이 없으면 게이트가 자동 통과된다(반 미배정 강사가 제출을 막히지 않도록).

### 4.3 상태 전이 (일일보고)

```
(없음) --작성/임시저장--> draft --제출--> submitted --팀장 확인--> submitted+confirmed
                            ^                 |                        |
                            +---강사 수정------+                   (수정 불가)
```

- BR-STATE-1: `confirm`은 `status='submitted'`에만 유효(미제출이면 400) — 미제출 확인이 빈 draft를 만드는 것을 방지.
- BR-STATE-2: `reopen`은 `confirmed=1`이면 400.
- BR-STATE-3: `submit`은 `confirmed`를 항상 `false`로 초기화한다.
- BR-STATE-4: 화면 표시상 `confirmed`는 `status='submitted' && confirmed`로만 참이 된다.

### 4.4 권한 경계

- BR-PERM-1 (업무 가시성): 강사는 본인이 담당(`assignees`에 포함)인 업무만 받는다.
- BR-PERM-2 (보고 격리): 강사에게 내려가는 업무의 `statuses`는 **본인 항목만** 남기고 마스킹된다(타 강사 보고 텍스트·첨부 유출 방지).
- BR-PERM-3 (강사 목록): 강사에게는 `teachers` 배열에 본인만 내려간다.
- BR-PERM-4 (제출 현황): 전원 제출 현황(`todayReports`)은 팀장에게만 내려간다.
- BR-PERM-5 (일정 가시성): §3.7 FR-EVT-2.
- BR-PERM-6 (외부 ERP 자료): 출결·상담·성적·로스터는 강사 본인 외부 ERP 계정으로만 조회된다(FR-TTT-1).
- BR-PERM-7 (비밀번호): 외부 ERP 비밀번호는 암호화 저장되고 API 응답에는 `tttId`와 `hasTtt` 불리언만 포함된다.
- BR-PERM-8 (고정 태그): `상담` 태그는 삭제·이름변경 불가(FR-TAG-2).
- BR-PERM-9 (배너): 공지 배너는 강사 화면에만 노출된다.
- BR-PERM-10 (특강 설정): 특강기간 변경·중앙 반 동기화는 API에서도 `role=lead`만 허용한다.
- BR-PERM-11 (상담 본인 바인딩): 강사 역할의 상담 조회·로스터 동기화·엔트리 완료/전송은 세션 계정의 본인 이름으로 제한한다.
- BR-PERM-13 (행위자): 요청의 행위자는 세션 쿠키로만 정한다. 요청의 `role`은 그 계정이 가진 권한(팀장·강사·다른 팀) 안에서 화면 선택으로만 받아들이고, 요청의 `tid`는 행위자 판단에 쓰지 않는다.
- BR-PERM-14 (팀장 전용 변경): 업무 생성·수정·삭제, 태그·공지·설정 변경, 일일보고 확인 처리는 팀장 역할만 한다.
- BR-PERM-15 (본인 처리): 강사 역할의 업무 처리 상태·MT·보고 저장과 일일보고 조회·임시저장·제출·재수정은 본인 이름으로만 한다.
- BR-PERM-16 (출처 검사): 상태를 바꾸는 요청은 같은 출처(Origin, 없으면 Sec-Fetch-Site)에서 온 것만 받는다.
- BR-PERM-12 (다른 팀 격리): 다른 팀 역할은 본인이 만든 `self_managed` 상담일정과 최신 동기화 본인 반에만 접근할 수 있다. 상태 응답에서도 내부 강사명·팀 일정·공지·일일보고 정의/제출 현황을 제거하고 `상담` 태그만 남긴다. 일반 업무·보고·설정·공지 변경과 다른 인원의 상담/알림장 접근은 API에서 거부한다.

### 4.5 날짜 규칙

- BR-DATE-1: 모든 날짜는 ISO `YYYY-MM-DD`로 저장하고 라벨(`7월 11일 (토)`)·D-day는 계산한다.
- BR-DATE-2: 앱 기준 '오늘'은 **KST 실제 날짜**. `APP_TODAY` 환경변수가 있으면 그 값으로 고정(로컬/데모용).
- BR-DATE-3: 요일 그룹 — 월·수·금 → `월수금반`, 화·목·토 → `화목토반`, **일요일 → 해당 없음(null)**.
- BR-DATE-4: 반 이름에 `T`가 있으면 T반으로 보아 `wtest_t`, 아니면 `wtest_m`을 성적 조회일로 쓴다.
- BR-DATE-5: 로스터 동기화는 외부 ERP에서 **해당 반의 오늘 이하 가장 최근 수업일** 출결을 현재 재원생 명단으로 사용한다(결석생 포함, 퇴원생 제외).
- BR-DATE-6: 특강 보고 여부는 전역 현재값이 아니라 `journals.special_period` 생성 스냅샷을 사용한다. 그 날 처리 반은 일반 요일 그룹과 대응하는 특강 요일 그룹의 합집합이다.

`src/db/schema.ts` 기준 주요 테이블.

| 테이블 | 키 | 비고 |
| --- | --- | --- |
| `teachers` | `tid` | `classes`(동기화 전용·읽기 전용 정규/특강 M/T JSON), `ttt_id`/`ttt_pw`(암호화), `is_lead`, `is_other_team` |

| `counsel_entries` | `id`, UNIQUE `(task_id, teacher, cls, scode)` | `synced`, `content` 보존 |
| `special_class_roster` | `(source_month, class_code, scode)` | 월별 특강 반·학생 캐시; 특강상담 생성 시 `counsel_entries`로 고정 복사 |
| `other_team_syncs` / `other_team_classes` / `other_team_students` | `(teacher_tid, source_month, …)` | 다른 팀 사용자의 월별 본인 반·학생 스냅샷 |
| `events` | `id` | `owner` = `'lead'`\|`'team'`\|강사 `tid` |
| `settings` | `k` | `wtest_m` / `wtest_t` + 특강 토글·기준일·최근 월/시각/요약 |
| `notices` | `id` | `sort`(노출 순서), `active` |

- 저장소는 libSQL. `TURSO_DATABASE_URL`이 있으면 Turso 임베디드 리플리카(원격이 진실), 없으면 로컬 파일 SQLite.
- 서버리스 읽기-후-쓰기 일관성: 상태 조회 전 원격 pull, 변경 후 원격 sync.
- `SEED_MODE=demo`면 데모 시드, 기본(`clean`)은 팀장 계정 + 기본 태그만 생성한다.

## 6. 알려진 제약 / 미구현

모두 코드에서 확인된 사항이다.

### 데이터 연결
1. `task_status`·`daily_reports`가 강사 **이름** 문자열로 연결돼 있다. 동명이인이나 이름 변경 시 데이터가 어긋날 수 있다(이름 변경 UI는 없다).

### 미구현 기능
2. 태그 정렬(`tags.sort`) 변경 UI가 없다(공지만 드래그 재정렬 지원).

### 연동 제약
3. 공개 저장소의 외부 ERP 구현은 모의 구현뿐이다. 모의 구현은 응답 지연·세션 만료·저장 거부를 흉내 내지 않으므로, 확인 불가와 재확인 경로는 `tests/counsel-write.test.cjs`의 가짜 포트로 검증한다.

### 기타
4. 첨부파일은 base64 data URL로 DB(payload/`report_files`)에 인라인 저장되며 파일당 4MB로 제한된다. 별도 파일 스토리지가 없다.
5. API 함수의 `maxDuration`은 120초다(서버리스 배포 기준). 클라이언트는 일반 요청 28초, 특강 반·상담 로스터 동기화·상담 전송은 125초에서 중단해 서버의 명확한 오류 응답을 우선 기다린다.
6. 팀장 대시보드 공지 요약은 마크다운을 렌더하지 않고 원문을 한 줄로 자른다(`text-overflow: ellipsis`).
7. 특강 도메인과 상담 쓰기 확인 규칙은 `npm test`로 자동 검증하고, GitHub Actions가 push와 PR마다 테스트·`npx tsc --noEmit`·빌드를 돌린다. **브라우저 E2E는 없다.** ESLint는 설정하지 않아 빌드에서 건너뛴다.
