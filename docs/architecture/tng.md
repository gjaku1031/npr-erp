# 외부 ERP 연동

반·학생·출결·성적·알림장·상담은 학원이 이미 쓰고 있는 외부 ERP가 원장이다. 이 저장소에는 그 연동의
**포트 하나와 가상 데이터를 돌려주는 대역 어댑터**만 있다. 결정 배경은 [ADR-0009](../adr/0009-single-tng-port-with-mock-adapter.md)에 있다.

## 포트

`tng` 모듈의 `TngGateway`가 유일한 경계다. 업무일지는 이 인터페이스만 안다.

| 읽기 | 쓰기 |
|---|---|
| 직원 목록, 직원의 담당 반, 반의 학생 명단 | 알림장 게시 |
| 그날의 출결, 과제 이행, 주간테스트 성적 | 상담 기록 |
| 그날의 알림장, 직원이 남긴 상담 기록 | |

돌려주는 타입은 이 저장소가 정한 `record`다. 외부 ERP의 화면 구조나 필드 이름은 포트 밖으로 나오지 않는다.

쓰기가 실패하면 `TngGatewayException`이 "외부가 처리하지 않은 것이 확실한가"를 함께 알린다. 확실한 거부만 호출자가
되돌릴 수 있고, 시간 초과나 연결 끊김처럼 결과를 모르는 실패는 호출자가 기록을 확인한 뒤에 다시 보내야 한다.
어댑터는 이 둘을 구분해 던져야 한다.

## 대역 어댑터

`MockTngGateway`는 입력(직원 코드, 반 코드, 날짜)에서 결정적으로 값을 만든다. 같은 요청에는 항상 같은 답을 준다.
게시한 알림장과 보낸 상담은 프로세스 메모리에 둔다. 사람 이름, 학교, 연락처는 모두 지어낸 값이다.
수업이 없는 요일에는 출결이 비어 있다.

## 두지 않은 것

실제 외부 ERP를 상대할 때 필요한 장치는 대역 앞에서는 검증할 수 없어 두지 않았다. 실제 어댑터를 붙일 때 필요하다.

| 장치 | 실제 연동에서 필요한 이유 |
|---|---|
| 직원별 외부 계정과 로그인 세션 관리 | 외부 ERP가 직원 본인 계정으로만 자료를 내줌 |
| 전송 선점의 만료(lease) | 선점한 프로세스가 죽었을 때 다른 요청이 이어받기 위함 |
| 명단이 줄어드는 동기화의 재확인 | 일시적인 조회 실패를 학생이 빠진 것으로 오인하지 않기 위함 |
| 정규 반 담당자 충돌 해소 | 한 반이 여러 계정에 보일 때 담당자를 정하기 위함 |
| 수강년월 탐색 | 특강 반이 달마다 다른 분류에 놓이기 때문 |

업무일지 쪽에는 연동 방식과 무관한 것만 둔다: 전송 상태(`IDLE → PENDING → SENT`)와 대조,
가져온 명단이 비어 있으면 아무것도 지우지 않는 규칙, 써 둔 상담 내용을 명단 갱신에서 보존하는 규칙.
