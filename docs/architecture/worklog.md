# 업무일지

팀장이 업무를 내고, 강사가 처리하고 날마다 일일보고를 제출하는 기능이다. 사람은 계정 ID로 가리키고
누가 무엇을 할 수 있는지는 권한 엔진이 정한다. 결정 배경은 [ADR-0010](../adr/0010-worklog-on-account-ids-and-permissions.md)에 있다.

## 기능

| 기능 | 내용 |
|---|---|
| 업무 | 일반(직접 완료 표시), MT(월수금·화목토를 각각 체크), 전체 상담, 특강상담, 개인 상담일정 |
| 완료 조건 | 일반 업무에 "텍스트 보고 필수", "첨부 필수"를 걸 수 있음. 채우지 않으면 완료로 표시되지 않음 |
| 상담 | 반 명단을 가져와 학생별로 쓰고 외부 ERP로 보냄. 전원에게 보내면 업무가 완료됨 |
| 일일보고 | 날짜별 체크리스트를 정하고, 다섯 단계(체크리스트·알림장·상담 확인·출결 확인·업무 확인)를 마치면 제출 |
| 그 밖 | 공지(마크다운, 순서, 노출), 캘린더와 일정, 태그, 담당 반 연결 |

## 역할 대신 권한

업무일지는 팀장·강사·다른 팀 같은 역할 이름을 보지 않는다.
학원이 역할을 만들고 `worklog.*` 권한을 고른다.

`worklog`는 권한 엔진에 의존하지 않으므로 "누가 대상인가"를 스스로 정하지 못한다. 컨트롤러가 엔진에서 구해 넘긴다.

| 집합 | 정하는 기준 | 쓰는 곳 |
|---|---|---|
| 업무를 받는 사람 | `worklog.task.perform`을 가진 계정 | 전원 배정의 담당자, 담당자 후보, 완료 집계의 분모 |
| 일일보고를 쓰는 사람 | `worklog.report.write`를 가진 계정 | 제출 현황의 분모 |

전원 배정 업무의 담당자는 **조회할 때의 집합**으로 계산한다. 역할이 바뀌면 다음 조회부터 담당자가 달라진다.
특강상담만 예외로, 만들 때의 담당자와 학생 명단을 고정한다.

"본인의 것" 조건은 자료를 가진 `worklog`가 계정 ID로 확인한다.

- 담당자가 아닌 업무는 처리하거나 보고할 수 없다.
- 담당자에게 내려가는 업무에는 본인의 보고와 첨부만 들어 있다. 다른 담당자의 것은 서버에서 뺀다.
- 상담, 알림장, 출결은 가져온 본인 담당 반 안에서만 열린다.
- 개인일정과 개인 상담일정은 만든 사람만 본다. 공용 업무를 다루는 메서드는 개인 상담일정을 찾지 못하고,
  삭제는 만든 사람인지 확인하는 별도 메서드로만 한다.
- 제출한 일일보고의 첨부, 완료한 업무의 완료 조건이던 보고와 마지막 첨부는 지우거나 비울 수 없다.

## 상담 전송

같은 상담이 외부 ERP에 두 번 기록되지 않아야 한다. 상담 행이 전송 상태를 가진다.

```text
IDLE ──(내용 저장 + 선점, 커밋)──▶ PENDING ──(외부 호출 성공, 커밋)──▶ SENT
  ▲                                   │
  └──────(외부가 명확히 거부)──────────┘
```

외부 호출은 두 트랜잭션 사이에서 한다. `PENDING`이 커밋된 뒤로는 같은 상담을 다시 보낼 수 없다.
포트가 "외부가 처리하지 않은 것이 확실함"이라고 알린 실패만 `IDLE`로 되돌린다. 응답을 받지 못한 실패와
호출 뒤 확정 전에 끊긴 경우는 `PENDING`으로 남는다. 이때는 외부 ERP의 그날 상담 기록에서 같은 학생·주제·내용을 찾아,
있으면 `SENT`로 확정하고 없으면 `IDLE`로 되돌린다. 사람이 "외부 기록과 대조"를 눌러 실행한다.

대조는 내용이 같은지로 판정한다. 같은 학생에게 같은 날 같은 주제와 내용의 기록이 따로 있었다면 보내지 않은 상담을
보낸 것으로 판정하고, 외부 ERP가 저장하면서 내용을 바꾸면 보낸 상담을 찾지 못한다. 외부 ERP가 요청 식별자를 받아
돌려주지 않는 한 남는 한계다. 지금의 대역 어댑터는 실패하지 않으므로 이 흐름은 포트를 대역으로 바꾼 테스트로만 확인했다.

## 일일보고 제출

다섯 단계의 완료 여부는 서버가 계산한다. 화면이 보낸 완료 표시는 받지 않는다.

| 단계 | 완료 조건 | 서버가 읽는 곳 |
|---|---|---|
| 체크리스트 | 항목이 있고 전부 체크, 필수 항목에는 확인 결과 | 저장된 답 |
| 알림장 | 그날 담당 반이 없거나 모든 반에 게시 | 외부 ERP |
| 상담·출결 확인 | 확인 표시 | 저장된 답 |
| 업무 확인 | 그날이 기간에 드는 일반 업무를 모두 완료 또는 미완료로 표시 | 업무 원장 |

상태는 `작성 중 → 제출 → 확인`으로만 나아간다. 작성자는 확인 전까지만 제출을 되돌릴 수 있고, 다시 제출하면
확인 표시가 지워진다. 제출하는 순간의 담당 반, 알림장 게시 여부, 업무 상태를 보고에 적어 둔다.
나중에 담당 반을 다시 가져오거나 업무 상태가 바뀌어도 낸 보고는 달라지지 않는다.
특강기간 여부도 날짜를 만들 때의 값을 적어 두어, 설정을 나중에 꺼도 그날의 반 목록이 바뀌지 않는다.

## 저장

상태 전이가 있는 것(업무, 처리 상태, 상담, 일일보고, 직원 설정, 태그)은 JPA Entity가 규칙을 가진다.
행 단위 자료(체크리스트, 설정, 공지, 일정, 첨부)와 집계는 jOOQ로 읽고 쓴다.
첨부는 파일 하나에 4MB까지 DB에 두고, 목록을 읽을 때는 본문을 올리지 않는다.

업무 조회는 학원의 업무 전체(보관 포함)를 읽어 조립한다. 업무 수에 비례하며 수천 건 규모를 가정한다.
일일보고의 제출 조건 계산과 제출 기록은 한 트랜잭션이 아니다. 상태 전이만 행 잠금으로 보호한다.
