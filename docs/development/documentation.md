# 문서 작성 규칙

## 원칙

문서 본문은 **루트 `docs/`에 Markdown(`.md`)으로 작성한다. 한국어로 읽기 쉽고 간결하게,
현재 작업에 필요한 내용만 남긴다.** 한 개념의 설명은 한 문서가 소유하고 다른 문서는 링크한다.

프로젝트·앱 루트의 `README.md`는 문서 진입 링크와
반드시 그 위치에 있어야 하는 짧은 지침만 허용한다. 생성된 의존성 문서는 관리 대상이 아니다.

## 배치

| 위치 | 담을 내용 |
|---|---|
| `development/` | 실행 방법, 코드·문서 규칙, 현재 범위 |
| `architecture/` | 현재 구조, 경계, 중요한 불변조건 |
| `operations/` | 실행 가능한 운영·복구 절차 |
| `integrations/` | 외부 계약, 필드 사전, ERD, 검증 근거 |
| `adr/` | 결정 하나당 번호가 있는 기록 |

## 작성·갱신

- 문서마다 H1 제목 하나를 두고, 결론·용도부터 적는다. 일반 설명은 150줄 이내를 목표로 한다.
- 과도한 중첩 제목, 같은 결론의 반복, 교과서식 개념 설명, 회의·작업 중계와 TODO 전용 문서를 만들지 않는다.
- 표는 비교·계약에, 코드 블록은 바로 쓸 명령·설정에 사용한다. 실행 디렉터리와 필요한 환경을 명시한다.
- 긴 필드 사전·ERD·외부 검증 원장은 필요한 상세를 보존하되 요약·목차를 제공한다. 길이만 줄이려고 계약을 삭제하지 않는다.
- 상대 링크와 소문자 `kebab-case.md` 파일명을 사용한다. wiki 전용 문법·절대 로컬 경로에 의존하지 않는다.
- `현재 구현`, `제안`, `미구현`, `과거 검증`을 구분한다. 검증 결과에는 날짜와 범위를 적고 미래 완료를 단정하지 않는다.
- 문서 이동 시 진입점, 내부 링크와 문서를 읽는 테스트도 함께 변경한다. 중복 파일·빈 색인·대체된 실행 안내는 제거한다.
- 비밀값과 개인정보는 예시에도 넣지 않는다. 원본 artifact·fixture·마이그레이션은 설명 문서가 아니므로 임의 변형하지 않는다.

## ADR

`NNNN-짧은-결정명.md`에 상태·날짜·맥락·결정·대안·결과를 짧게 기록한다.
새 제안은 `Proposed`, 명시적으로 승인된 결정은 `Accepted`로 표시한다.
기존 결정을 바꾸면 새 번호를 추가하고 이전 ADR에 `Superseded` 또는 부분 대체 관계를 표시한다.
과거 결정의 의미를 현재 구현처럼 다시 쓰거나 번호를 재사용하지 않는다.

## 확인

```bash
# 프로젝트 루트
python3 scripts/check-docs.py
```

새 문서는 상위 색인에서 찾을 수 있어야 한다.
