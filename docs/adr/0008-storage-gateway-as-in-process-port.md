# ADR-0008: 저장소를 프로세스 안의 포트로 두고 로컬 파일시스템 어댑터를 사용

- 상태: **Accepted**
- 날짜: 2026-10-10
- 관계: 트리·휴지통 계약은 [ADR-0005](0005-storage-tree-mutations-and-trash-lifecycle.md)

## 맥락

파일을 NAS에서 도는 별도 게이트웨이가 다루는 구성을 함께 검토했다. 그 구성에서는 애플리케이션이 게이트웨이에
제어 요청을 보내고, 브라우저가 짧은 전송 권한을 받아 게이트웨이와 직접 주고받으며, 게이트웨이가 자체 원장으로
중복 요청을 거른다. 실제 NAS 배포를 전제로 하므로 로컬에서는 시뮬레이션으로 대신해야 한다.

## 결정

저장소를 `storage` 모듈 안의 포트 `StorageGateway`로 두고, 어댑터는 로컬 파일시스템 하나만 둔다.

- 작업 원장을 두고 `기록 → 호출 → 확정`의 순서로 실행한다. 포트의 연산은 작업 UUID로 멱등하다.
- 재시작 때 끝나지 않은 작업을 확인 대상으로 표시하고, 운영자가 멱등한 재실행으로 마무리한다.
- 올리기는 임시 이름으로 받아 크기와 해시를 확인한 뒤 확정한다.
- 별도 게이트웨이 프로세스, 전송 권한 발급, 게이트웨이 원장은 두지 않는다.

## 결과

배포 단위가 하나이고 로컬과 운영의 경로가 같다. 작업 원장의 실패 처리는 저장소가 디스크일 때도 필요하다:
이동이나 삭제 도중 프로세스가 끊기면 DB와 디스크가 어긋나기 때문이다.
NAS나 오브젝트 저장소로 옮기려면 어댑터를 추가해야 하며, 그때 브라우저 직접 전송이 필요할 수 있다.
