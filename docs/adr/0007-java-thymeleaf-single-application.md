# ADR-0007: Java와 Thymeleaf의 단일 애플리케이션

- 상태: **Accepted**
- 날짜: 2026-10-10
- 관계: 저장소 포트는 [ADR-0008](0008-storage-gateway-as-in-process-port.md)

## 맥락

한 사람이 개발하고 운영한다. API, 화면, 파일 게이트웨이를 별도 런타임으로 두면 빌드·배포·디버깅 대상이 늘고,
화면과 API 사이의 세션·CSRF 전달, 게이트웨이와의 전송 권한 발급처럼 프로세스 경계 때문에 생기는 계약이
업무 기능보다 많아진다.

## 결정

Java, Spring Boot, Spring Modulith, JPA, jOOQ, Thymeleaf, PostgreSQL의 **단일 애플리케이션**으로 만든다.

- 화면은 서버가 그린다. 폼 로그인과 폼에 든 CSRF 토큰을 쓰고, 별도 JSON API와 API 문서는 두지 않는다.
- 파일은 애플리케이션을 거쳐 올리고 내려받는다. 저장소는 포트 뒤에 둔다([ADR-0008](0008-storage-gateway-as-in-process-port.md)).
- 공개 계약은 모듈 루트, 구현은 `internal`에 두고 Modulith 검증으로 경계를 지킨다.

## 대안

| 대안 | 채택하지 않은 이유 |
|---|---|
| API 서버 + 별도 프런트엔드 애플리케이션 | 화면을 만들 때마다 두 코드베이스와 그 사이 계약을 함께 늘려야 함 |
| API 서버 + SPA | 화면이 폼과 목록 위주여서 클라이언트 상태 관리의 이득이 작음 |

## 결과

런타임이 JVM 하나다. 화면 요청마다 권한 엔진을 거치는 자리가 컨트롤러 한 곳으로 모인다.
파일 본문이 애플리케이션을 지나가므로 큰 파일의 전송 부하를 애플리케이션이 진다.
화면 전환마다 전체 페이지를 다시 받는다. 다른 클라이언트(모바일 앱)가 필요해지면 JSON API를 새로 만들어야 한다.
