# ADR-0005: Storage 트리 변경과 명시적 휴지통 생명주기를 도입한다

> 상태: Accepted  
> 결정일: 2026-09-01  
> 결정자: NPR 프로젝트  

## 컨텍스트

처음에는 목록·다운로드·업로드가 안정화될 때까지 Move, Rename과 실제 Delete를 미루기로 했다.
파일 관리자의 범위를 구체화하면서 이동, 이름 변경, 복원 가능한 휴지통과 명시적인 영구 삭제를 초기 Storage Core에 포함하기로 결정했다.

## 결정

### 1. Storage Core가 트리 변경을 소유한다

`storage` 모듈은 다음 동작과 불변조건을 소유한다.

- 시스템 루트와 파일·폴더 트리
- 같은 폴더 안의 정규화 이름 유일성
- 폴더 생성, 이름 변경과 이동
- 자기 자신 또는 자기 하위 폴더로의 이동 금지
- 서브트리 단위 휴지통 이동과 원래 위치 복원
- 휴지통 최상위 항목만 가능한 영구 삭제
- 시스템 루트의 이동·이름 변경·휴지통·삭제 금지

최종 이동 검증은 항상 `storage` 유스케이스가 수행한다.

### 2. 외부 변경은 Storage Operation Ledger를 거친다

폴더 생성, 이름 변경, 이동과 영구 삭제는 다음 순서를 사용한다.

```text
짧은 준비 트랜잭션
→ 외부 Gateway 호출
→ 짧은 완료 또는 실패 트랜잭션
```

외부 호출 중 PostgreSQL 트랜잭션을 유지하지 않는다. Node는 `PROVISIONING`, `MUTATING` 또는
`DELETING` 상태로 동시 변경을 차단하고, Operation은 실패와 외부 참조를 보존한다.

### 3. 휴지통은 자동 만료하지 않는다

휴지통 이동은 외부 파일을 즉시 변경하지 않는 논리 상태 전이다. 자동 보존 기간이나 주기적 purge는
도입하지 않는다. 사용자가 영구 삭제를 명시적으로 실행할 때만 Gateway가 외부 서브트리를 삭제하고
로컬 Node를 `DELETED` tombstone으로 확정한다.

휴지통 항목의 원래 외부 경로를 보존하므로 같은 위치와 이름은 영구 삭제 또는 복원 전까지 다시 사용할
수 없다. 다른 폴더로 복원하는 기능은 외부 Move 복구 정책을 추가한 뒤 확장한다.

## 결과

- 경로 기반 외부 저장소의 부분 실패를 작업 원장에서 추적할 수 있다.
- 권한 편집기와 직원 동기화 없이 Storage Core를 독립적으로 테스트할 수 있다.
- 영구 삭제는 복구 불가능하므로 휴지통 선행과 사용자 확인이 필수다.
